### 5. Diferències entre XML i Markdown
a) L'opció B (Markdown) és més ràpida d'escriure i més fàcil de llegir, perquè té menys etiquetes i el text és més clar.

b) Un sistema informàtic preferiria XML perquè les dades estan organitzades amb etiquetes i atributs. Això fa que els programes puguin identificar, interpretar i processar la informació de manera estructurada.

### 6. Per què Markdown és l'estàndard dels README.md a GitHub?
Perquè és fàcil d'escriure, llegir i modificar. A més, GitHub el mostra amb el format aplicat, de manera que els títols, les llistes, els enllaços i els blocs de codi es veuen ordenats i clars.

### 7. Beneficis d'un README.md ben estructurat
Com a desenvolupador, és més còmode trobar un fitxer README.md perquè puc llegir la documentació directament a GitHub sense descarregar cap fitxer. També perquè està ben organitzat, és fàcil de consultar i em permet trobar ràpidament com instal·lar i utilitzar la llibreria amb exemples de codi i enllaços.

### 8. Quin format utilitzaria en cada cas?
- **Cas 1: Markdown:** L'utilitzaria per escriure apunts o una guia d'instal·lació perquè és senzill, fàcil de llegir i permet organitzar la informació amb títols, llistes i exemples de codi.

- **Cas 2: XML:** L'utilitzaria perquè permet guardar les dades dels usuaris de manera estructurada, amb etiquetes que fan que sigui fàcil que una aplicació les pugui llegir i processar.
